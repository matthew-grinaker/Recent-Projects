What Claude gets from Fleet

  • Eyes on my machineLive

    Through Fleet's tools, any Claude session on my Mac, including the coordinator, can list, read and message the others, instead of me carrying messages between them.

  • Fewer stallsLive

    Questions reach me wherever I am: one ranked inbox, Mac notifications with quiet hours, Slack and my phone.

  • Safer autonomyNext

    A local policy gate that lets reversible actions through and holds the irreversible ones for me, so sessions can run unattended for longer.

  • A feedback loopNext

    Repeated corrections and approvals turned into proposed rules, skills and allow rules, written back into Claude.

  • Better use of my planNext

    Background work paced around the five-hour limit instead of every session hitting it at once.

What Fleet gets from Claude

  • IntelligenceLive

    On request, a small Claude model reads what a session is waiting on and drafts the likely answer with its confidence. It is only ever shown to me, and Fleet never sends it on its own.

  • A brain it never has to buildLive

    Memory, threads, files and decisions stay in Claude. Fleet links to them and never copies them.

  • Everything Claude makes, in one placeLive

    Files, artifacts and PRs from every session on my Mac in one library, with documents saved into the project's OUTPUTS folder.

  • DistributionLive

    Fleet ships as a Claude Code plugin with an MCP server and a skill. Hooks and a status line come next.

  • A source of workNext

    The coordinator hands tasks to workers on my Mac through Fleet.

Why it matters

What changes day to day

Every minute an agent waits on me is agent time lost. Fleet is built to cut it.

An agent needs an answer while I'm away

BeforeThe question waits on a screen nobody is looking at, and every agent behind it waits too.
With FleetIt reaches me in Slack or on my phone, ranked by how much agent time it is holding up, and I answer it there.

Sessions need to coordinate

BeforeI copy context from one terminal to another and act as the go-between.
With FleetSessions ask Fleet what else is running in the repo and message each other directly.

Work runs in three places

BeforeLocal sessions, cloud sessions and project threads each live in a different window.
With FleetOne view and one inbox cover all three, with project threads grouped by project beside their checklist.

A session finishes in the cloud or a scratchpad

BeforeDocuments are lost when the container is reclaimed, unless I remember to copy them.
With FleetEvery output shows in Fleet's library, and documents are saved into the project's folder.
